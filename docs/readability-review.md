## Round 1 — 2026-09-26 — scope: every source file except `components/ui`

About 55 files and 4.8k lines on branch `skill-pass` at 9a34656: `lib/` (31 files), `components/app/`
(14) and `app/` (10). `components/ui` is generated by shadcn and never edited (repo rule).

**Method.** A TypeScript AST scan for nested ternaries (it found 4 of 4 planted cases before it
was run on the repo, then 13 candidates here); a grep for re-exports; two read-only agents, one
for `lib/` and one for the UI, each reading every file in full. Every finding was re-checked in
the file before it went into the plan.

- `app-store.ts` `activeLocationId` "whose rooms and due tasks are shown": only the Due tab reads it.

- `operations.ts` "duplicate, move, then edit": duplicate already takes the destination.
- `use-display-settings.ts` "theme and size": also the start screen.
- `routes.ts` "See app/page.tsx": now `app/(app)/page.tsx`.
- `core/index.ts` "never from the individual files": except `z` from `./zod`.
- `backup.ts`: the compact copy never carries display settings; the nudge comment now names
  `FIRST_BACKUP_NUDGE_DAYS` / `BACKUP_NUDGE_DAYS` instead of copying their values.

- `due-screen.tsx` "The home screen … across all rooms": it is the Due tab at `/due`.

  back on the toaster. "Every screen" now says every app screen (`/about` has its own layout).
- `intro.tsx` "(Settings > Show the intro)": the button says "Show the intro tutorial".
- `node-row.tsx` "room card": a folder row.

  opens tasks), "location" for the top level only, and "item" in screen text.

**B. Renames.**
- `NodeRow` prop `location` → `parentPath`. It held "Home › Kitchen", while "location"
  everywhere else means a top-level node.
- `CORRUPT_BACKUP_KEY` → `UNREADABLE_BACKUP_KEY`, matching `hasUnreadableBackup` and the key's
  own value. The stored key string (`sincewhen:unreadable-backup`) did not change.
- `BackupSummary` fields `tasks` / `folders` / `completions` (numbers that read like arrays)
  → `taskCount` / `folderCount` / `completionCount`.
- `undoCompletion`: `entry` meant a log entry, then an undo record, two lines apart →
  `completion` / `before`.
- `intro.tsx` module-level `setOpen` / `subscribe` / `listeners`, which read like a
  `useState` setter → `setIntroOpen` / `subscribeToIntro` / `introListeners`.

**C. Nested ternaries.**
- `node-form.tsx` name validator (3 outcomes, trimmed twice) → a function with early returns.
- `node-form.tsx` last-done date validator (4 outcomes, mis-indented) → early returns behind a
  named `isPickingDate`. Equivalent by De Morgan; not clicked through in the browser.
- `node-screen.tsx` the same top / task / folder choice written twice → `screenKind()` plus
  `EMPTY_TEXT` and `ADD_LABEL` maps (plain strings, so evaluation order does not matter).
- `intro.tsx` Next / Done / Start buttons (3 outcomes, the first negated) → `ForwardButtons`
  with early returns.
- Left as they are: `node-form.tsx:89` and `:101` (short, commented), a pluralization in
  `node-sheet.tsx`, an optional suffix in `settings-screen.tsx`, the empty state in
  `due-screen.tsx`, the sort tiebreak in `tree.ts`.

**D. Hard-coded values.**
- `href="/rooms"` in 3 links → `roomHref(null)`. The tab table in `app-shell.tsx` keeps its
  literal paths: it is itself the list of routes.
- `"#ffffff"` in `app/layout.tsx` and `app/manifest.ts` → `BAR_COLOR.light`, now exported.
- `START_SCREEN_HREF` now `satisfies Record<StartScreenChoice, string>`; a planted missing
  choice failed typecheck.

**Bugs the review found (behavior changes, approved separately).**
1. Moving the location the Due tab was filtered to inside another one left the tab filtered with
   no way to clear it (see `docs/pitfalls.md`). `moveNode` in the store now falls back to all
   locations. A new test failed before the fix and passes after.
2. Settings showed "(1 days ago)", "1 tasks in 1 folders" and "the 1 items". It now uses the
   `plural()` helper from `lib/format.ts`, which is exported for this.
